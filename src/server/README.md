# Server modules

The current server owns FalkorDB access and deterministic promise checks. Local explicit checks, synthetic rollout writes, and reversible missing-test scenario transitions produce persisted ActivityEvent records; each check also stores a status-only ReviewRun snapshot. The review module provides guarded proposal creation, approve/reject, stale-basis checks, and explicit resume. `agent/tools.ts` is the shared validated registry for the local Responses API assistant and stdio MCP server. The browser must not connect directly to FalkorDB or receive provider credentials.

The assistant endpoint is same-origin and local-development-only. It requires `OPENAI_API_KEY`, accepts at most 2,000 characters, allows two concurrent requests, and limits each model turn to four sequential named-tool calls. Prompt and synthetic tool output are sent to OpenAI; assistant checks may also save a local status-only history entry. Do not submit sensitive information. Assistant proposal tools return an unsaved preview; the user must explicitly create a pending proposal, which still requires a separate human approval before application.
